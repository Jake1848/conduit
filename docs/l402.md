# L402 agent payments

Let an AI agent call a paywalled (`HTTP 402` / **L402**) API and have Conduit
pay the Lightning toll automatically from a policy-capped agent wallet — no
Lightning keys in the agent, hard spend limits it can't exceed.

L402 is the Lightning-native "pay-per-request" scheme: a server answers `402
Payment Required` with a `WWW-Authenticate: L402 macaroon="…", invoice="…"`
challenge; the client pays the invoice, then retries with
`Authorization: L402 <macaroon>:<preimage>`. Conduit turns that loop into one
call.

## Two surfaces

### 1. MCP tool — `conduit_fetch_paid` (zero agent code)

Any MCP-capable agent (Claude, GPT tool-use, LangChain-MCP, …) can call:

```jsonc
// tool: conduit_fetch_paid
{ "agent": "research-bot", "url": "https://api.example.com/paid", "max_sats": 2000 }
```

It returns a structured result:

```jsonc
{ "status": 200, "body": "…", "paid_sats": 210, "cached": false, "preimage_used": true }
```

Unsupported protocols, over-cap payments, and domain refusals come back as
`{ "error": "…", "error_type": "…" }` rather than throwing — the agent sees a
machine-readable failure. `preimage_used` is a boolean: the tool never echoes
the preimage itself (it's a bearer secret).

### 2. SDK middleware — `fetch_with_l402` / `L402Client` (Python)

```python
from conduit import Agent
from conduit.l402 import L402Config
from conduit.l402_fetch import fetch_with_l402, L402Client

agent = Agent.create(name="research-bot", daily_limit=50_000)

# One-shot:
r = fetch_with_l402("https://api.example.com/paid", agent=agent, sats=210)
print(r.status, r.body)

# Reused client — a service-wide token is bought once and reused (no re-pay):
with L402Client(agent, config=L402Config(max_auto_pay_sats=2_000)) as http:
    a = http.fetch("https://api.example.com/v1/a")
    b = http.fetch("https://api.example.com/v1/b")   # cached token, paid_sats == 0
```

Non-402 responses pass through unchanged. A TypeScript `fetchWithL402` mirrors
this in `@conduit-btc/sdk`.

## Guardrails

Client-side guards layer **on top of** Conduit's server-side spending policy
(which is the hard guarantee — an over-limit pay is rejected in the ledger
before any sats move). Configure them with `L402Config`:

| Option | Effect |
| ------ | ------ |
| `max_auto_pay_sats` | Refuse any single toll above this (a second cap on top of the server policy). |
| `allowed_domains` / `denied_domains` | Only pay (or never pay) these hosts. |
| `approve(challenge) -> bool` | Human-approval tier for over-cap tolls; default-deny when absent. |
| `max_repays_per_resource_window` | Cap re-pays per resource per fetch (default 1) — see below. |
| `audit` | A sink called for every decision (paid / cached / re-paid / refused / approved) with a reason. |

## How the token cache and re-pay guard keep you safe

- **Token cache is keyed by the macaroon's *scope*, not the URL.** An L402
  macaroon often authorizes a whole service or an N-call quota; its caveats are
  the real scope. Conduit parses the caveats (`services`, `capabilities`,
  `valid_until`, `count`) and reuses a token for any request its scope covers —
  re-validating expiry/quota before every reuse — so you don't re-buy a token
  you already hold, and you don't reuse one the caveats no longer permit.
- **Re-pay guard against silent double-spends.** If a request still returns
  `402` *after* a successful payment, Conduit does not blindly re-pay. It
  classifies the second challenge — a *same* macaroon+invoice means the token
  was rejected (clock skew / revocation), so it refuses; a genuinely *new*
  challenge is allowed once per fetch, then capped. (Conduit's server-side
  idempotency is keyed on the invoice, and a fresh challenge carries a new
  invoice, so this client guard is the only thing standing between you and a
  real double payment.)

## Self-hosted vs hosted

The SDK and MCP server talk to whatever Conduit instance you point them at
(`CONDUIT_API_URL`). The default and recommended path is **your own**
Conduit + LND — non-custodial, your node, your keys. A hosted instance works
too, at the cost of trusting that host with your sats.

## A note on the preimage

The payment preimage satisfies the L402 challenge, so it's a **bearer secret**.
Conduit returns it only in the synchronous, write-scoped `POST /pay` and `/send`
response — to the caller who made the payment. It is never returned by a
read-scoped GET/list surface, so a low-privilege read key can't harvest
preimages and replay paid access. The L402 engine consumes the preimage to build
the auth header and never surfaces it back to the agent.

## Scope

L402 (Lightning) only today. The engine has a protocol-detection seam so x402
(stablecoin 402) can be added later without restructuring; a non-L402 challenge
raises `UnsupportedChallenge` for now.
